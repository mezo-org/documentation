**[x402](https://x402.org)** — открытый стандарт нативных интернет-платежей.
Сервер возвращает ответ `HTTP 402 Payment Required` с машиночитаемым описанием
стоимости; клиент прикладывает подписанное платёжное сообщение и повторяет
запрос; фасилитатор проводит расчёт по платежу ончейн, и сервер возвращает
клиенту квитанцию вместе с купленным контентом.

В Mezo актив расчётов по умолчанию — **MUSD**. Продавец назначает цену,
например $0,01, x402 SDK во время выполнения переводит её в сумму в MUSD
(18 десятичных знаков, `permit2` + EIP-2612), а кошелёк покупателя подписывает
сообщение, которое авторизует перевод в пределах заданного временного окна.

## Платёжный процесс в общих чертах

<Image
  src={x402MezoFlow}
  alt="Диаграмма последовательности платежа x402 в Mezo: клиент/покупатель, продавец/сервер, фасилитатор (facilitator.vativ.io) и блокчейн Mezo (eip155:31611)."
/>

1. `Client` отправляет HTTP-запрос на `server`.

2. `Server` отвечает статусом `402 Payment Required` и возвращает объект `PaymentRequired` в кодировке b64 в HTTP-заголовке `PAYMENT-REQUIRED`.

3. `Client` выбирает одно из `PaymentRequirements`, возвращённых в ответе сервера, и создаёт `PaymentPayload` на основе `scheme` и `network` выбранного `PaymentRequirements`.

4. `Client` повторяет HTTP-запрос к серверу, теперь добавив HTTP-заголовок `PAYMENT-SIGNATURE` с `PaymentPayload`.

5. `Server` проверяет, что `PaymentPayload` действителен, — либо локально, либо отправив `PaymentPayload` и `PaymentRequirements` POST-запросом на эндпоинт `/verify` фасилитатора (`facilitator`).

6. `Facilitator` проверяет объект на основе `scheme` и `network` из `PaymentPayload` и возвращает `Verification Response`.

7. Если `Verification Response` действителен, сервер выполняет работу по запросу. Если `Verification Response` недействителен, сервер ресурса возвращает статус `402 Payment Required` и JSON-объект `Payment Required Response` в теле ответа.

8. `Server` проводит расчёт по платежу либо напрямую взаимодействуя с блокчейном, либо отправив `Payment Payload` и `Payment PaymentRequirements` POST-запросом на эндпоинт `/settle` фасилитатора (`facilitator`).

9. `Facilitator` отправляет платёж в блокчейн на основе `scheme` и `network` из `Payment Payload`.

10. `Facilitator` ждёт подтверждения платежа в блокчейне.

11. `Facilitator` возвращает серверу `Payment Execution Response`.

12. Если платёж успешно выполнен, `Server` возвращает `Client` ответ `200 OK` с запрошенным ресурсом в теле HTTP-ответа и заголовок `PAYMENT-RESPONSE`, содержащий `Settlement Response` в виде JSON в кодировке Base64.

## Как MUSD вписывается в x402

- **Идентификатор сети:** сеть Mezo идентифицируется строками CAIP-2 —
  тестовая сеть Mezo — `eip155:31611`, основная сеть Mezo — `eip155:31612`
  (x402 не принимает короткие имена вроде `"mezo-testnet"`).
- **Определение актива:** цены в x402 задаются долларовыми строками
  (`price: "$0.01"`). Реестр `DEFAULT_STABLECOINS` из `@x402/evm` во время
  выполнения сопоставляет их с нужным токеном MUSD для выбранной сети — вам не
  нужно жёстко прописывать адрес актива в конфигурации маршрутов.
- **Подпись:** MUSD — токен с поддержкой `permit2` + EIP-2612, поэтому
  авторизация платежа — это одна подпись EIP-712, без ончейн-транзакции
  одобрения и без газа на стороне покупателя.
- **Фасилитатор:** расчёты в обеих сетях проводит один и тот же фасилитатор,
  `https://facilitator.vativ.io`, который обслуживает тестовую и основную сети
  через один эндпоинт.

### Справочник Mezo x402

Актуальный SDK сам определяет актив и прокси расчётов во время выполнения;
значения ниже приведены для справки и проверки ончейн — прописывать их в коде
не нужно. Между тестовой и основной сетями различаются только **ID сети** и
**актив MUSD**:

| Сеть | CAIP-2 | Актив MUSD (18 десятичных знаков) |
|---|---|---|
| Mezo Testnet | `eip155:31611` | `0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503` |
| Mezo Mainnet | `eip155:31612` | `0xdD468A1DDc392dcdbEf6db6e34E89AA338F9F186` |

Всё остальное в обеих сетях одинаково:

| Параметр | Значение |
|---|---|
| Фасилитатор | `https://facilitator.vativ.io` (обслуживает обе сети) |
| Прокси расчётов | `0x402085c248EeA27D92E8b30b2C58ed07f9E20001` — каноническое развёртывание через CREATE2, SDK определяет его автоматически |
| Домен EIP-712 | имя `Mezo USD`, версия `1` — отличается от символа `MUSD` |
| Способ перевода | `permit2` + EIP-2612 |

## Почему Mezo для x402

Большинство сетей с поддержкой x402 проводят расчёты в USDC. Mezo предлагает
другое:

- **Нативный для биткоина актив расчётов.** MUSD выпускается под залог BTC в
  экономике Mezo. Выручка в MUSD остаётся в экосистеме биткоина — без
  промежуточной конвертации через ETH или централизованных эмитентов
  стейблкоинов.
- **Точность 18 десятичных знаков для настоящих микроплатежей.** Списание
  $0,001 — полноценная операция, а не погрешность округления. API с
  тарификацией по использованию, оплата ИИ за каждый инференс и доступ к
  контенту за каждый запрос могут иметь реалистичные цены без пакетирования.
- **Ноль газа для покупателей (фасилитатор платит в BTC).** Фасилитатор Mezo
  по адресу `facilitator.vativ.io` оплачивает каждую ончейн-транзакцию расчёта
  в нативных BTC. Покупателям (включая ИИ-агентов) нужны только MUSD для оплаты
  и приватный ключ для подписи авторизации EIP-712 permit2: не нужно пополнять
  BTC для газа, не нужен перенесённый через мост токен газа, не нужно заранее
  пополнять баланс перед первым платежом.
- **Предсказуемая экономика сети.** Mezo изначально построен вокруг финансовых
  примитивов, обеспеченных биткоином, поэтому предложение MUSD и стоимость
  займов подчиняются правилам, привязанным к базе залога в BTC, а не политике
  эмитента стейблкоина.

## Что можно создать

x402 + MUSD в Mezo подходит везде, где продавцу нужно нативное для HTTP
ценообразование без управления подписками, API-ключами или аккаунтами в
платёжных системах:

- **Платный контент.** Статьи, стримы, отчёты, подборки исследований.
  Один `402` на каждый защищённый URL, цена — за каждый ресурс.
- **API с тарификацией по использованию.** Взимайте плату за каждый запрос к
  погодным данным, криптофидам, аналитическим эндпоинтам или собственной
  бизнес-логике. Никакой возни с лимитами запросов и никакого жизненного цикла
  API-ключей.
- **ИИ-сервисы с оплатой за инференс.** Оберните LLM, генератор изображений,
  STT, эмбеддинги или дообученную модель в эндпоинт x402. Вызывающие платят за
  каждый вызов по реальной себестоимости — это возможно благодаря 18 десятичным
  знакам MUSD.
- **Платежи между машинами (M2M).** ИИ-агенты с клиентом `@x402/fetch` и
  приватным ключом проводят транзакции автономно: находят платный инструмент,
  читают требования `402`, проводят расчёт и используют результат. Без
  аккаунтов, без обмена учётными данными, без участия человека в каждом
  платеже. Поскольку газ оплачивает фасилитатор, агенту нужны только MUSD и
  ключ для подписи — пополнять BTC перед началом транзакций не требуется.
- **Платные MCP-серверы.** Предоставляйте инструменты агентам через Model
  Context Protocol и тарифицируйте каждый вызов через x402. Естественно
  сочетается с автономными агентами-потребителями.
- **Замена SaaS-подписок оплатой по использованию.** Замените подписочную
  модель оплатой за каждое использование для инструментов, дашбордов или
  внутренних сервисов с неравномерной или непредсказуемой нагрузкой.
