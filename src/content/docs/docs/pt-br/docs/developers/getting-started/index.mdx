## 1. Introdução ao Mezo

O Mezo foi projetado para transformar o Bitcoin de uma reserva de valor passiva em um ativo financeiro produtivo e dinâmico. Ao combinar a segurança do Bitcoin com a flexibilidade de uma blockchain moderna, o Mezo oferece uma plataforma robusta para aplicações descentralizadas (dApps) que atendem à enorme e mal atendida comunidade Bitcoin.

### 1.1 Arquitetura principal

A cadeia do Mezo é construída sobre uma arquitetura híbrida, projetada para oferecer o máximo de acessibilidade e desempenho aos desenvolvedores.

- Compatibilidade com EVM: o Mezo é uma blockchain totalmente compatível com EVM, o que permite que desenvolvedores Solidity implantem contratos inteligentes existentes e usem ferramentas conhecidas, como Hardhat e Foundry, com o mínimo de alterações no código.
- Base no Cosmos SDK: o cliente principal, `mezod`, é um fork fortemente modificado do Evmos, construído com o Cosmos SDK e operando com o mecanismo de consenso CometBFT. Isso garante soberania de cadeia e alta vazão.
- BTC como gás: todas as taxas de transação no Mezo são pagas em BTC, reforçando a utilidade do Bitcoin como ativo transacional.
- Cliente principal: a implementação de referência do cliente da cadeia do Mezo é o `mezod`.

## 2. Início rápido: tempo até a primeira transação (TTFT)

Esta seção apresenta o caminho mais rápido para implantar um contrato e interagir com a Mezo Testnet.

### 2.1 Detalhes da rede (Testnet)

Para configurar sua carteira (por exemplo, MetaMask, RainbowKit) ou seu ambiente de desenvolvimento, use os seguintes parâmetros da Testnet:

| Parâmetro | Valor |
| --- | --- |
| Nome da rede | Mezo Testnet |
| Endpoint RPC (HTTPS) | `https://rpc.test.mezo.org` |
| Endpoint RPC (WSS) | `wss://rpc-ws.test.mezo.org` |
| Chain ID | `31611` |
| Moeda nativa | BTC |
| Casas decimais | 18 |
| Explorador de blocos | [explorer.test.mezo.org](https://explorer.test.mezo.org/) |

### 2.2 Obtenha BTC de testnet

Para pagar as taxas de gás na Testnet, você precisará de BTC de testnet.

<Steps>
1. Faucet do Mezo: obtenha BTC de testnet no [Mezo Faucet](https://faucet.test.mezo.org/) oficial.
   - Observação: o faucet é protegido por um CAPTCHA para evitar abusos.

2. Configuração da carteira: certifique-se de ter instalada uma carteira de navegador compatível com Ethereum (EVM).
</Steps>

### 2.3 Configuração do ambiente (exemplo com Hardhat)

Para desenvolvedores Solidity, o Mezo é totalmente compatível com Hardhat e Foundry.

Para configurar o Hardhat para a Mezo Testnet, modifique seu arquivo `hardhat.config.js` (ou `.ts`):

```javascript
module.exports = {
  defaultNetwork: "mezotestnet",
  networks: {
    mezotestnet: {
      url: "https://rpc.test.mezo.org",
      chainId: 31611,
      accounts: ["YOUR_PRIVATE_WALLET_KEY"] // Use environment variables for security
    }
  },
  solidity: {
    version: "0.8.28",
    settings: {
      evmVersion: "london",
      optimizer: {
        enabled: true,
        runs: 200
      }
    }
  },
};
```

## 3. Componentes principais de desenvolvimento

### 3.1 Stablecoin MUSD

O MUSD é a stablecoin nativa do ecossistema Mezo, lastreada em Bitcoin. Os desenvolvedores podem integrar o MUSD para pagamentos, liquidez e produtos financeiros.

- Repositório: os contratos inteligentes e a implementação do dApp estão disponíveis no repositório do MUSD no GitHub: [mezo-org/musd](https://github.com/mezo-org/musd).
- Ambiente de desenvolvimento (pnpm):

```bash
pnpm install --frozen-lockfile
cd solidity
pnpm install --frozen-lockfile
```

- Testes dos contratos:

```bash
cd solidity
pnpm test
```

- Implantação (exemplo): os contratos podem ser implantados com o comando `pnpm run deploy` dentro do diretório `solidity`. Consulte o repositório para mais detalhes: [mezo-org/musd](https://github.com/mezo-org/musd).

### 3.2 Integração com o Mezo Passport (opcional)

O Mezo Passport é a biblioteca oficial de conexão de carteiras, construída sobre o RainbowKit, que permite uma conexão fluida tanto de carteiras Bitcoin nativas (por exemplo, Xverse, Unisat) quanto de carteiras EVM padrão (por exemplo, MetaMask). A integração é opcional e não é necessária para desenvolver no Mezo.

Instalação:

```bash
npm install @mezo-org/passport @rainbow-me/rainbowkit wagmi viem@2.x @tanstack/react-query
```

Configuração (React/TypeScript):

Use o método `getConfig` de `@mezo-org/passport` para configurar seu `WagmiProvider`.

```tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { RainbowKitProvider } from "@rainbow-me/rainbowkit";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { WagmiProvider } from "wagmi";
// Note: We use the consistent 'mezoTestnet' chain name for clarity.
import { getConfig, mezoTestnet } from "@mezo-org/passport";

const queryClient = new QueryClient();

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <WagmiProvider config={getConfig({ appName: "Your Mezo dApp" })}>
      <QueryClientProvider client={queryClient}>
        <RainbowKitProvider initialChain={mezoTestnet}>
          {/* Your App component */}
        </RainbowKitProvider>
      </QueryClientProvider>
    </WagmiProvider>
  </React.StrictMode>,
);
```

## 4. Infraestrutura e operação de nós

O Validator Kit é o principal recurso para configurar e executar um nó do Mezo: [mezo-org/validator-kit](https://github.com/mezo-org/validator-kit).

### 4.1 Requisitos de hardware dos nós

Estas são as especificações mínimas de hardware recomendadas para executar os diferentes tipos de nós do Mezo:

| Tipo de nó | vCPU | RAM | Disco |
| --- | --- | --- | --- |
| Validador | 4 | 16 GB | 256 GB |
| RPC | 8 | 32 GB | 512 GB |
| Seed | 2 | 8 GB | 128 GB |

### 4.2 Opções de implantação

O Validator Kit oferece vários métodos de implantação, que atendem a diferentes níveis de complexidade operacional:

<Steps>
1. Docker: recomendado para a configuração mais simples, usando o Docker Compose.

2. Nativo: execução direta do binário `mezod`.

3. Helm: para implantação em clusters Kubernetes.

4. Manual: guia passo a passo para controle manual completo.
</Steps>

### 4.3 Onboarding de validadores (Prova de Autoridade)

Os validadores do Mezo precisam se candidatar à Prova de Autoridade (PoA) para participar do consenso.

- Comando de candidatura: depois de configurar seu nó, envie sua candidatura usando a CLI do `mezod`:

```bash
mezod --home=<mezod_home_path> --rpc-url <rpc_url> poa submit-application <key_name>
```
