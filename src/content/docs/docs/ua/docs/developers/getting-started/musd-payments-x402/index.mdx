**[x402](https://x402.org)** — це відкритий стандарт нативних інтернет-платежів. 
Сервер повертає відповідь `HTTP 402 Payment Required` з
машинозчитуваним описом вартості; клієнт додає підписане
платіжне повідомлення й повторює запит; фасилітатор проводить розрахунок ончейн, 
а сервер повертає клієнту квитанцію разом з придбаним контентом. 

У Mezo типовим активом для розрахунків є **MUSD**. Продавець указує ціну, наприклад $0,01, 
SDK x402 під час виконання перетворює її на суму в MUSD
(18 десяткових знаків, `permit2` + EIP-2612), а гаманець покупця підписує 
повідомлення, яке авторизує переказ у межах обмеженого часового вікна. 

## Платіжний потік коротко

<Image
  src={x402MezoFlow}
  alt="Діаграма послідовності платіжного потоку x402 у Mezo: Client/Buyer, Merchant/Server, Facilitator (facilitator.vativ.io) і Mezo Blockchain (eip155:31611)."
/>

1. `Client` надсилає HTTP-запит до `server`.

2. `Server` відповідає статусом `402 Payment Required` і повертає об'єкт `PaymentRequired` у кодуванні b64 в HTTP-заголовку `PAYMENT-REQUIRED`.

3. `Client` вибирає одну з `PaymentRequirements`, повернених у відповіді сервера, і створює `PaymentPayload` на основі `scheme` і `network` вибраних `PaymentRequirements`.

4. `Client` повторює HTTP-запит до сервера, цього разу з HTTP-заголовком `PAYMENT-SIGNATURE`, що містить `PaymentPayload`.

5. `Server` перевіряє валідність `PaymentPayload` або локально, або надсилаючи `PaymentPayload` і `PaymentRequirements` POST-запитом на ендпоінт `/verify` фасилітатора (`facilitator`).

6. `Facilitator` перевіряє об'єкт на основі `scheme` і `network` з `PaymentPayload` і повертає `Verification Response`.

7. Якщо `Verification Response` валідна, сервер виконує роботу для обробки запиту. Якщо `Verification Response` невалідна, сервер ресурсу повертає статус `402 Payment Required` і JSON-об'єкт `Payment Required Response` у тілі відповіді.

8. `Server` проводить розрахунок за платежем або напряму через блокчейн, або надсилаючи `Payment Payload` і `Payment PaymentRequirements` POST-запитом на ендпоінт `/settle` фасилітатора (`facilitator`).

9. `Facilitator` надсилає платіж у блокчейн на основі `scheme` і `network` з `Payment Payload`.

10. `Facilitator` чекає, доки платіж буде підтверджено в блокчейні.

11. `Facilitator` повертає серверу `Payment Execution Response`.

12. Якщо платіж виконано успішно, `Server` повертає `Client` відповідь `200 OK` із запитаним ресурсом у тілі HTTP-відповіді та заголовком `PAYMENT-RESPONSE`, що містить `Settlement Response` у вигляді JSON, закодованого в Base64.

## Як MUSD вписується в x402

- **Ідентифікатор мережі:** мережу Mezo ідентифікують рядки CAIP-2 — Mezo
  Testnet має `eip155:31611`, Mezo Mainnet — `eip155:31612` (x402 не
  приймає короткі назви на кшталт `"mezo-testnet"`).
- **Визначення активу:** ціни в x402 — це рядки в доларах (`price: "$0.01"`).
  Реєстр `DEFAULT_STABLECOINS` у `@x402/evm` під час виконання зіставляє їх із
  правильним токеном MUSD для вибраної мережі — вам не потрібно жорстко задавати
  адресу активу в конфігурації маршрутів.
- **Підписування:** MUSD — це токен `permit2` + EIP-2612, тож авторизація платежу
  — це один підпис EIP-712, без ончейн-транзакції дозволу (approve) і без
  газу з боку покупця.
- **Фасилітатор:** розрахунки в обох мережах проводить той самий фасилітатор,
  `https://facilitator.vativ.io`, який обслуговує Testnet і Mainnet з одного
  ендпоінта.

### Довідка x402 для Mezo

Актуальний SDK сам визначає актив і проксі для розрахунків під час виконання;
наведені нижче значення — для довідки та ончейн-перевірки, жорстко задавати їх
не потрібно. Між Testnet і Mainnet відрізняються лише **ідентифікатор мережі** та
**актив MUSD**:

| Мережа | CAIP-2 | Актив MUSD (18 десяткових знаків) |
|---|---|---|
| Mezo Testnet | `eip155:31611` | `0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503` |
| Mezo Mainnet | `eip155:31612` | `0xdD468A1DDc392dcdbEf6db6e34E89AA338F9F186` |

Усе інше в обох мережах однакове:

| Параметр | Значення |
|---|---|
| Фасилітатор | `https://facilitator.vativ.io` (обслуговує обидві мережі) |
| Проксі для розрахунків | `0x402085c248EeA27D92E8b30b2C58ed07f9E20001` — канонічне розгортання CREATE2, SDK визначає його автоматично |
| Домен EIP-712 | name `Mezo USD`, version `1` — відрізняється від символу `MUSD` |
| Метод переказу | `permit2` + EIP-2612 |

## Чому Mezo для x402

Більшість мереж, що підтримують x402, проводять розрахунки в USDC. Mezo пропонує інше:

- **Актив для розрахунків, нативний для Bitcoin.** MUSD випускається під заставу
  BTC в економіці Mezo. Дохід, номінований у MUSD, залишається в
  екосистемі Bitcoin без проміжного обміну через ETH чи централізованих
  емітентів стейблкоїнів.
- **Точність до 18 десяткових знаків для справжніх мікроплатежів.** Платіж $0,001 —
  повноцінна операція, а не похибка округлення. API з оплатою за обсяг,
  тарифікація ШІ за кожен інференс і доступ до контенту за кожен запит можуть
  мати реалістичні ціни без пакетування.
- **Нуль газу для покупців (фасилітатор платить у BTC).** Фасилітатор
  Mezo на `facilitator.vativ.io` спонсорує кожну ончейн-транзакцію розрахунку
  в нативних BTC. Покупцям (зокрема ШІ-агентам) потрібні лише
  MUSD для оплати та приватний ключ для підписання авторизації EIP-712 permit2;
  не потрібно поповнювати BTC для газу, мати перенесений через міст токен газу
  чи попередньо фінансувати гаманець перед першим платежем.
- **Передбачувана економіка мережі.** Mezo створено спеціально навколо
  фінансових примітивів, забезпечених біткоїном, тож пропозиція MUSD і вартість
  позик підпорядковуються правилам, прив'язаним до бази застави в BTC, а не
  політиці емітента стейблкоїна.

## Що можна створити

x402 + MUSD у Mezo підходять скрізь, де продавець хоче встановлювати ціни нативно
через HTTP без керування підписками, API-ключами чи рахунками в платіжних процесорах:

- **Платний контент.** Статті, трансляції, звіти, масиви досліджень.
  Один `402` на кожну захищену URL-адресу, ціна — за кожен ресурс.
- **API з оплатою за обсяг.** Стягуйте плату за кожен запит до даних про погоду, криптовалютних
  потоків даних, аналітичних ендпоінтів чи власної бізнес-логіки. Жодної
  мороки з лімітами запитів, жодного життєвого циклу API-ключів.
- **ШІ-сервіси з оплатою за інференс.** Обгорніть LLM, генератор зображень, STT,
  модель ембедингів чи донавчену модель в ендпоінт x402. Клієнти платять за кожен
  виклик за собівартістю — це можливо завдяки 18 десятковим знакам MUSD.
- **Платежі між машинами (M2M).** ШІ-агенти з клієнтом
  `@x402/fetch` і приватним ключем проводять транзакції автономно:
  знаходять платний інструмент, зчитують вимоги `402`, проводять розрахунок і користуються ним.
  Жодних облікових записів, обміну обліковими даними чи участі людини в кожному
  платежі. Оскільки газ спонсорує фасилітатор, агенту потрібні лише MUSD
  і ключ для підписання; поповнювати BTC, щоб почати проводити транзакції, не потрібно.
- **Платні MCP-сервери.** Надавайте інструменти для агентів через Model Context
  Protocol і встановлюйте ціну за кожен виклик через x402. Природно поєднується
  з автономними агентами-споживачами.
- **Заміна SaaS на оплату за використання.** Замініть оплату за підпискою
  на оплату за кожне використання для інструментів, дашбордів чи внутрішніх сервісів, де
  використання нерівномірне або непередбачуване.
